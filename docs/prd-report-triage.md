# PRD · 탕방 제보함 (`report_desk`)

- 작성: 2026-11-10 KST · 상태: 사용자 승인(시안 기준) → 구현 1차
- 한 줄: 사이트에서 들어온 제보를 **받아서 → 근거를 확인하고 → 반영**까지 한 화면에서 끝내는 운영자용 프로그램. 내 PC에서만 돈다.
- 관련: `.claude/skills/price-report`(같은 절차를 Claude가 할 때), `worker/src/index.js` `postReport`(받을 때 검사), `scripts/d1_publish.mjs`(`reports`·`report-set`·`ingest`·`diff`·`publish`)

## 1. 왜 만드나

제보는 Cloudflare D1 `reports` 표에 쌓이고, 지금은 `/price-report`로 Claude에게 시켜야만 확인·반영할 수 있다.

- 제보를 보는 화면이 없다. 터미널 한 줄 출력뿐이라 제보 값과 지금 화면 값을 나란히 보기 어렵다.
- 판단 기준(이상값·중복·충돌)이 글로만 있어 돌릴 때마다 달라질 수 있다.
- 반영은 파일 두 개(`onsen_prices.csv`·`place_facts.json`)를 손으로 고치고 상태를 따로 바꿔야 해서 빠뜨리기 쉽다.

지금 규모(2026-11-10 17:47 KST, `reports <상태>`로 셈): new 1건, 나머지 0건. 데이터가 많이 쌓이지 않고 모든 곳을 직접 가 볼 수도 없으므로 **검수는 계속 사람이 한다**(사용자 결정 2026-11-10). 나중에 AI가 근거를 미리 채워 주더라도 반영 버튼은 사람이 누른다.

## 3. 범위

**1차에 넣는 것**
1. 제보함: 새 제보를 업체별로 묶고 칩과 볼 순서를 붙여 보여 준다.
2. 제보 내용: 칸마다 제보 값과 지금 화면 값(확인일·출처)을 나란히 보여 준다.
3. 근거 확인: 카카오맵·네이버 지도 검색을 여는 링크, 근거에서 본 값 입력, 출처 고르기.
4. 판정: 반영 / 반려 / 확인 못 함. 반영은 `data/curated/`에 적고 제보 상태·검토 메모를 한 번에 바꾼다.
5. 내보내기: 화면 데이터 다시 만들기 → 초안 올리고 차이 보기 → 공개(버튼을 눌러야만).
6. 예시 모드(`--demo`): 가짜 제보로 화면을 보고, 파일·DB는 아무것도 바꾸지 않는다.

**넣지 않는 것**
- 제보만으로 자동 반영, 근거 자동 찾기(나중에 AI가 입력란을 미리 채우는 자리는 남긴다).
- 웹 운영자 화면, 수집 앱 탭.
- 이미 수집된 후기·가격표를 프로그램 안에서 보여 주기(2차).
- 제보 삭제. 제보는 지우지 않고 상태로만 관리한다.
- Worker·D1 표 변경.

## 4. 흐름

```
cargo run --release --bin report_desk          → 브라우저에 제보함이 열림 (http://127.0.0.1:8765)
cargo run --release --bin report_desk -- --demo → 예시 제보로 보기 (아무것도 안 바뀜)
```

1. 정리 대상이 있으면 '한 번에 처리'로 먼저 치운다(목록을 보여 주고 확인받음).
2. 왼쪽 제보함에서 업체를 고른다. 칸마다 제보 값, 지금 화면 값, 수집해 둔 네이버 근거(`naver_home_facts.csv`의 가격표·수건·세신·드라이기 문장)가 함께 보인다. 더 봐야 하면 네이버 플레이스·카카오맵 링크를 연다.
3. 근거에서 본 칸에만 `맞음`(수건·드라이기는 어느 탕인지까지) 또는 `다름`(값 입력)을 고른다. 안 고른 칸은 '못 봄'이라 반영되지 않는다.
4. 출처(마지막에 고른 것이 기억됨)를 확인하고 `반영`을 누른다. 확인 창 없이 바로 처리되고 다음 업체로 넘어간다. 잘못 눌렀으면 `되돌리기`(직전 한 번: 파일을 판정 전으로, 제보를 다시 new로).
5. 모아서 `화면에 내보내기` → 차이를 보고 `공개`(확인 한 번).

## 5. 제보함 칩 (볼 순서대로)

| 순서 | 칩 | 조건 |
| --- | --- | --- |
| 1 | 새 정보 | 지금 값이 없는 칸을 채우는 제보 |
| 2 | 인상 가능성 | 확인된 입장료보다 높은 값이고, 제보가 확인일보다 뒤 |
| 3 | 확인값과 다름 | 확인값이 있는데 제보 값이 다름 |
| 4 | 충돌 | 같은 업체·같은 칸에 서로 다른 값의 제보 |
| 5 | 이미 반영됨 | 제보에 적힌 값이 모두 지금 값과 같음 |
| 6 | 반려 추천 | 값이 전부 허위 기준에 걸림 / 업체가 지금 서비스 목록에 없음 |
| 7 | 시험 | 업체ID `TEST`, 업체·메모에 `시험` |

- 허위·의심 기준 숫자는 `data/report_rules.json`에만 있다. Worker가 받을 때 붙이는 표시(`입장료 이상값` 등)는 판단에 쓰지 않는다. 표시 기준은 이 파일과 같게 맞췄다(2026-11-10: 입장료 3,000원 미만·30,000원 이상, 수건 5,000원 초과, 세신 5,000원 미만·60,000원 초과). Worker는 허위와 의심을 나누지 않고 '이상값' 하나로 표시한다. 숫자를 바꾸면 `worker/src/index.js`·`web/api/report.js`의 `RANGE`도 같이 고치고 `node worker/test/run-local.mjs`(이 파일의 경계값으로 시험)를 통과시킨 뒤 Worker를 배포한다.
- 의심 값은 칩을 바꾸지 않고 '의심' 표시만 붙인다(사람이 더 조심해서 본다). 허위 값과 멀쩡한 값이 섞인 제보는 반려 추천이 아니라 사람이 본다.
- 같은 값 제보 건수는 참고로만 보여 준다. 건수가 많다고 사실로 치지 않는다.
- 칩은 추천일 뿐이고 상태를 바꾸지 않는다. '한 번에 정리'는 5~7번 묶음만 처리한다(시험·반려 추천 → `rejected`, 이미 반영됨 → `reviewed`).

## 6. 판정과 반영 규칙

| 판정 | 파일 | 제보 상태 | 검토 메모 |
| --- | --- | --- | --- |
| 반영 | '확인함'을 켠 칸만 `data/curated/`에 적는다 | 값이 근거와 같은 제보 `applied`, 근거와 다른 제보 `rejected`, 확인한 칸이 하나도 없는 제보 `reviewed` | 반영한 칸·근거 출처·날짜 |
| 반려 | 안 바꿈 | `rejected` | 사유(고름) + 날짜 |
| 확인 못 함 | 안 바꿈 | `reviewed` | 어디까지 봤는지 + 날짜 |

- 입장료·수건 요금 → `onsen_prices.csv`(`성인_평일`·`수건`·`출처`·`확인일`·`메모`). 다른 줄은 글자 하나도 바꾸지 않는다.
- 세신 요금·세신 결제·수건 안내·드라이기 → `place_facts.json`의 `places[업체ID]`. 수건·드라이기는 여탕·남탕을 따로 적는다(모르는 쪽은 적지 않는다).
- 출처에는 제보가 아니라 **확인한 근거**를 적고, 확인일은 오늘(KST).
- 파일을 먼저 쓰고 상태를 바꾼다. 상태 바꾸기가 실패하면 무엇이 됐고 무엇이 남았는지 알려 주고, 다시 눌러도 같은 결과가 된다.
- 업체ID가 줄 번호(`m…`)인 곳은 열쇠가 없어 반영할 수 없다. 반려·확인 못 함만 된다.

## 7. 안전

- `127.0.0.1`에서만 열린다. 요청의 Host가 로컬이 아니면 거절하고, 바꾸는 요청은 실행할 때 만든 토큰이 있어야 한다(다른 웹 페이지가 몰래 누르지 못하게).
- 관리 토큰·Worker 주소는 `d1_publish.mjs`만 다룬다. 프로그램은 그 JSON 출력만 읽고, 화면·로그에 내보내지 않는다.
- 제보자·접속 해시는 관리 도구가 내보내지 않으므로 다루지 않는다.
- 제보 내용은 `textContent`로만 화면에 넣는다.
- 공개는 차이를 보여 준 뒤 버튼을 눌렀을 때만 한다.

## 8. 완료 기준 (확인 가능한 문장)

1. `--demo`로 띄우면 예시 제보가 칩 7종으로 나뉘어 보이고, 판정을 눌러도 `data/curated/`와 D1이 바뀌지 않는다. → `git status data/curated`, 실행 전후 `reports new` 건수
2. 제보함 숫자(새 제보 수)와 목록의 제보 수 합이 같다. → 화면 숫자와 목록 비교
3. 표본 제보가 기대한 칩에 들어간다. → `cargo test --lib reportdesk`
4. 요금 반영은 `onsen_prices.csv`에서 해당 줄만 바꾸거나 새 줄을 더한다. → 시험: 나머지 글자가 같음
5. 정보 반영은 `place_facts.json`에서 해당 업체만 바꾸고 파일 모양(들여쓰기·줄 끝)이 같다. → 시험: 다시 쓴 결과에서 다른 업체 부분이 같음
6. 맞음·다름을 고른 칸이 하나도 없거나 출처가 없으면 반영되지 않고 안내가 뜬다. → 화면
6-1. 허위·의심 경계(2,999 / 3,000 / 30,000 / 39,999 / 40,000원, 확인값의 절반·두 배)가 기준대로 나뉜다. → `cargo test --lib reportdesk` `fake_and_suspect_rules`
6-2. 반려한 뒤 '되돌리기'를 누르면 제보가 다시 new가 된다. → 실제 모드에서 `reports new`·`reports rejected` 건수 (2026-11-10 확인: 2/0 → 0/2 → 2/0)
7. 실제 모드에서 새 제보 목록이 `reports new`와 같은 건수로 뜬다. → 건수 비교
8. 화면·터미널 출력에 토큰·Worker 주소·제보자 해시가 없다. → 출력 확인
9. 화면이 1440px에서 가로로 넘치지 않는다. → 요소 오른쪽 끝 좌표
10. `/price-report` 스킬, `docs/architecture.md`, `data/README.md`에 이 프로그램이 적힌다.
