# 탕방 데이터 수집 도구 · UI 맥락 문서 (다른 AI에게 주는 설명서)

이 문서는 **화면을 새로 디자인할 AI**에게 주는 맥락이다. 시각 디자인(색·글꼴·배치·스타일)은 정하지 않는다 — 함께 주는 레퍼런스를 따른다.
여기에는 **무엇을 보여 주고, 무엇을 할 수 있어야 하고, 어떤 상태가 있는지**만 적는다.

## 1. 무엇을 하는 프로그램인가
- **탕방**은 서울 동네 목욕탕 지도 서비스다(웹). 이 도구는 그 서비스의 데이터를 모으는 **운영자 PC용 데스크톱 앱**이다(윈도우·맥, Tauri + React). 서비스 사용자는 이 앱을 보지 않는다.
- 사용자: 운영자 1명. 프로덕트 디자이너이고 개발자가 아니다. 터미널 대신 버튼 하나로 수집하고, 결과를 눈으로 확인하고 싶다.
- 하는 일: 네이버 플레이스(홈·방문자 후기·블로그 원문과 사진·사진 탭)를 브라우저(ego)로 받아 → 정보를 판정해 → 서비스 화면 데이터를 만든다. 데이터를 서비스에 올리는(깃 커밋·푸시) 일은 앱이 하지 않고 사람이 Claude Code에게 부탁한다.
- 화면이 답해야 하는 질문 세 가지
  1. **지금 무엇을 하면 되나?** (수집)
  2. **얼마나 채웠고, 어디가 비었나?** (대시보드)
  3. **서비스에 실제로 어떻게 보이나?** (사진 고르기)

## 2. 화면 구성(정보 구조)
전역 요소: 앱 이름과 한 줄 설명 · 현재 한국 시간(KST) 시계 · 사용법 다시 보기 · 세 개의 화면 전환(수집 / 대시보드 / 사진 고르기, 수집 중이면 수집에 '실행 중' 표시) · 조건부 알림 "아직 서비스에 반영되지 않은 변경이 있어요"(바뀐 파일 목록 + Claude에게 할 말 "탕방 수집 결과 커밋하고 푸시해줘").

### 2-1. 수집
- **수집하기** (가장 중요한 영역)
  - 수집 방법 선택(둘 중 하나): `Claude와 함께`(Claude Code가 브라우저를 지휘하고 멈춘 이유를 알려 줌) / `직접 실행`
  - 다시 받기 선택: `안 함` / `30일 지난 곳` / `7일 지난 곳` + "YYYY-MM-DD 이전에 받은 페이지 N개"
  - 주요 행동 `수집 시작` (실행 중에는 `멈추기`)
  - 예상 시간: "예상 N분 · 오후 9:15쯤 끝나요", 근거 "받을 페이지 N개 · 최근 평균 곳당 11초 · 정리 1분"
  - 수집 규칙 안내(바꿀 수 없음): 곳당 10초 간격 · 한 번에 150곳까지 · 캡차가 보이면 바로 멈춤
  - 진행 단계 7개 — 단계마다 제목, 한 줄 설명, 상태
    1. 받을 목록 만들기 2. ego 브라우저로 받기 3. 받은 페이지 읽기 4. 정보 판정 5. 목록 합치기 6. 화면 데이터 만들기 7. 서비스에 반영하기(사람이 할 일)
  - 단계 상태: 대기 / 실행 중(진행률 n/N, 남은 시간) / 완료 / 멈춤(이유 문장) / 실패(이유 문장) / 7단계만 '할 일 있음'
  - 실행이 끝나면 결과 요약 문장(예: "받은 만큼 정리했어요. 캡차·보안 확인 화면이 보여서 멈췄어요. 우회하지 않아요. 나중에 다시 눌러 주세요.")
  - 보조: 단계 하나만 따로 실행하기, 실행 기록(로그) 보기 — 평소에는 접혀 있음
- **준비 상태**: 프로젝트 폴더 · 러스트(cargo) · ego 브라우저 · Claude Code 각각 준비됨/필요, 필요하면 고치는 방법 한 줄, 폴더 바꾸기. 필수 항목이 없으면 수집 시작을 막고 이유를 보여 줌.
- **지금 데이터**: 전체 곳 수, 네이버 연결 수, 후기·블로그 받은 곳, 마지막 수집일 같은 요약 숫자.
- **알아 둘 것**: 짧은 안내 노트.

### 2-2. 대시보드 (10년차 PO가 보는 관점: 커버리지 → 빈 곳 → 다음 할 일)
1. 데이터 기준일, `숫자 다시 읽기`(수집 없이 다시 계산)
2. **핵심 지표 5개**(전체 대비 %, "N / 전체곳"): 요금 확인 · TOP 3 정보(수건·드라이기·세신) · 네이버 연결 · 홈 수집 완료 · 30일 안 수집
3. **Claude 사용량**: 오늘·이번 달·전체(달러, 약 원화, 토큰, 호출 수) / 단계별 비중(ego 수집 지휘·사진 고르기·사진 글자 읽기, 1개당 비용) / 최근 14일 날짜별 비용 / 최근 호출 목록. "API 요금 환산값, 구독이면 사용 한도에서 빠짐" 안내 필요
4. 다음에 할 일(우선순위 목록) · 단계별 확보 현황 · 항목별 채움률 · 수집 신선도
5. 구별 커버리지(구마다 전체·연결·홈·요금·TOP 3, 정렬 가능)
6. 목록 탐색기: 필터(전체·대형 시설·요금 미확인·TOP 3 없음·네이버 미연결·ID 못 찾음·30일 넘은 수집) + 구 선택 + 이름 검색 + 정렬, 100곳씩 더 보기
7. 수집 기록(이 PC에서 실행한 기록: 언제·무엇을·방법·결과·저장 수·걸린 시간)

### 2-3. 사진 고르기
- 목적: 서비스 목록에 보일 대표 사진을 사람이 고른다. 순서 안내: ① 이 사진으로 정하기 → ② 화면 데이터에 반영 → ③ Claude에게 커밋·푸시 요청(세 번째까지 해야 서비스에 보임)
- 진행률(고른 곳 / 전체), `화면 데이터에 반영`
- 상태 거르기: 고를 곳 / 고름 / 후보 없음 / 전체
- **목욕탕 1곳 = 카드 1장**
  - 이름·구·종류, 상태(아직 안 고름 / 고름·종류 / 사진 없이 두기로 함)
  - 최근 활동 날짜: 마지막 사진 · 마지막 후기 · 마지막 블로그. 후기·블로그가 1년 넘게 없으면 경고 "영업 여부와 요금이 바뀌었을 수 있어요"
  - 후보 사진 여러 장 중 하나 고르기(지금 서비스 사진 표시) + `사진 없이 두기`
  - 사진 종류: 외관 / 내부 / 탕
  - **서비스 목록 카드 미리보기**: 고른 사진이 실제 서비스 목록에서 어떻게 보이는지 그대로 보여 줌(서비스의 목록 카드 컴포넌트를 재사용 — 이 미리보기만은 서비스 모양을 따라야 함)
  - 저장 버튼(실행 중에는 막힘)

### 2-4. 사용법 안내(온보딩)
- 실제 화면 요소를 차례로 가리키는 안내(약 11단계: 준비 상태 → 프로젝트 폴더 → 수집 방법 → 다시 받기 → 수집 시작 → 진행 단계 → 서비스에 반영하기 → 대시보드 지표 → 다음에 할 일 → 숫자 다시 읽기 → 사진 고르기). 첫 실행에만 자동으로 열리고 언제든 다시 볼 수 있음.

## 3. 반드시 지킬 동작 원칙
- 앱은 **커밋·푸시를 하지 않는다**. 반영이 필요하면 알림으로 사람이 할 일을 안내한다.
- 수집 규칙(10초 간격·150곳·캡차 멈춤)을 바꾸거나 우회하는 컨트롤을 두지 않는다.
- 실행 중에는 충돌하는 동작(사진 저장·폴더 바꾸기·사용법 열기·다른 실행)을 막고 이유를 보여 준다.
- 개발자용 설정·디버그 화면은 넣지 않는다.
- 숫자는 실제 데이터에서 계산한 값만. 추정은 "예상", "약"을 붙인다. 시간은 한국 시간.
- 상태는 색만으로 구분하지 않는다(글자·아이콘 함께). 키보드로 모든 조작 가능. 움직임 줄이기 설정 존중.

## 4. 문구 톤
- 한국어 해요체, 짧게. 개발 용어 대신 하는 일을 말한다("크롤링" → "페이지를 받아요").
- 멈춤·실패는 **이유 + 다음 행동**을 한 문장에.

## 5. 화면에 필요한 데이터(앱 내부 명령이 이미 제공)
| 명령 | 주는 것 |
| --- | --- |
| `check_env` | 준비 상태 항목(라벨, 준비 여부, 설명, 고치는 법) |
| `summary` | 받을 페이지 수, 수집 날짜들, 최근 속도(예상 시간 계산용) |
| `start(plan, engine, refresh_days)` / `stop` / `is_running` | 수집 실행·멈춤, 단계 상태·로그는 이벤트로 옴 |
| `fetch_status` | 받기 진행(done/total, 저장·빈 페이지, 멈춘 이유) |
| `dashboard` | 장소 목록, 수집·연결·판정 현황, 수집 기록, Claude 사용량 |
| `photos` / `pick_photo` | 사진 후보·고른 사진·최근 활동 날짜 / 사진 저장 |
| `publish_status` | 서비스에 반영 안 된 변경(파일 목록, 푸시 안 한 커밋 수) |
| `get_root` / `set_root` | 프로젝트 폴더 |

UI를 새로 만들 때 이 명령과 데이터 모양은 그대로 쓰고, 화면(`collector/src/`)만 바꾼다.

## 6. 다른 AI에게 부탁할 때
- 이 문서 + 운영자가 고른 **레퍼런스 이미지** + (필요하면) 현재 화면 캡처.
- 요청은 "어느 화면의 어떤 정보를, 레퍼런스의 어떤 느낌으로"처럼 구체적으로. 3장의 동작 원칙을 깨는 제안은 받지 않는다.
