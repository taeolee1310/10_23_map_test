# 요금 제보 확인·반영 (탕방)

사용자가 사이트에서 보낸 제보는 **단서**다. 화면에는 근거를 확인한 값만 올린다. 이 절차는 읽기 → 확인 → 제안 → (승인) → 반영 → 시트 갱신 순서로 간다.

- 시트: `탕방 요금 제보` (구글 드라이브, 파일 ID `1yTWOx_VCJy5XtXvJDVm0LRioSpveg3YYIilUQgaDG_A`, 나만 보기). `제보` 탭에 한 줄씩 쌓인다.
- 칸(1행 제목): 시각, 업체ID, 업체, 성인 입장료, 수건, 세신, 확인 방법, 메모, 표시, 같은 값 횟수, 상태, 검토 메모, 제보자(해시), 접속(해시), 수건 안내, 드라이기, 세신 결제
  (수건·세신은 **요금(원)**, 수건 안내·드라이기·세신 결제는 가기 전 걱정 정보(TOP 3)다. 제보는 요금만, 정보만, 둘 다 올 수 있다.)
- 모드: `확인`이면 1~4단계까지만(읽고 정리해서 보여 주기). `반영`이면 이미 승인된 항목만 5~7단계. 인자가 없으면 1~4단계 뒤에 사용자 승인을 받고 5~7단계로 간다.

## 1. 읽기
1. Google Drive 연결(`read_file_content`)로 파일 ID의 시트를 읽는다. 연결이 안 되거나 내용이 잘린 듯하면(줄이 비는 등) ego-browser로 시트를 열어 읽는다.
2. **1행 제목이 위 칸과 같은지 먼저 확인**한다. 다르면 멈추고 사용자에게 알린다(칸이 바뀌면 엉뚱한 칸을 읽는다).
3. 읽은 줄 수, 상태별 개수를 조건과 함께 적는다. 예: "제보 탭 전체 N줄 중 상태가 '새 제보'(또는 빈칸)인 줄 M줄".
4. 다음은 제외하고 개수를 알린다: 업체ID가 `TEST`이거나 업체/메모에 `[시험]`·`시험`이 든 줄(운영자 시험 줄), 상태가 이미 `반영 완료`·`반려`인 줄.
5. 새 제보가 없으면 "새 제보 없음"만 알리고 끝낸다.

## 2. 정리
업체별로 묶고, 제보마다 다음을 본다. 숫자는 코드로 센다.
- **표시 칸**: 이름 불일치 / 입장료·수건·세신 이상값 / 연락처 의심 / 업체 확인 못 함. 표시가 있으면 먼저 의심한다.
- **같은 값 횟수**: 참고만 한다. 한 사람이 여러 번 보내도 오른다(한 사람당 3번 제한이 있어도 우회될 수 있다). 횟수가 많다고 사실로 치지 않는다.
- **제보끼리 충돌**: 같은 업체에 값이 서로 다르면 모두 보여 준다.
- **지금 화면과 비교**: `web/public/data/onsen.json`의 해당 업체 `price`·`facts`와 비교한다(이미 확인된 값이 있으면 덮어쓰지 않는다. 더 강한 근거가 있을 때만 바꾸자고 제안한다).
- **업체ID 열쇠**: 카카오ID가 없는 곳(업체ID가 `lic…`로 시작, 98곳)도 `lic…` 값이 그대로 `onsen_prices.csv`·`place_facts.json`의 열쇠(카카오ID 칸)로 쓰인다(`export_web_data`가 같은 칸으로 찾는다). 시트의 업체ID를 그대로 열쇠로 쓰면 된다. 열쇠가 아예 비어 있는 2곳만 줄 번호(`m…`)라 반영하지 않고 "반영 불가"로 알린다.

## 3. 근거 확인 (제보만으로는 반영하지 않는다)
Claude가 **직접 볼 수 있는 근거**로만 확인한다.
- 이미 모은 자료: `data/collected/naver_places.csv`, 수집기 출력(`C:\Users\user\naver-crawl\out*/`), `data/curated/*`.
- 네이버 플레이스 가격표·사진, 업체 공식 홈페이지, 공공데이터(착한가격업소 등). 브라우저가 필요하면 ego-browser를 쓴다. 2차 수집이 돌고 있으면(`run-all2`/`collect2` 프로세스) 그 작업과 겹치지 않게 사용자에게 알리고 기다린다.
- **전화 확인은 제안하지도 넘기지도 않는다.** 근거를 못 찾으면 "확인 못 함"과 어디까지 찾아봤는지를 보고한다.

제보별 판정은 셋 중 하나다.
| 판정 | 뜻 | 시트 상태 |
|---|---|---|
| 일치 | 근거가 제보 값과 같다 | `반영 완료`(반영 뒤) |
| 불일치 | 근거가 제보 값과 다르다(또는 스팸·잘못된 제보) | `반려`(근거 값이 이미 있으면 그 값을 유지) |
| 확인 못 함 | 근거를 찾지 못했다 | `확인함`(단서로 남김, 반영 안 함) |

## 4. 제안 (여기서 멈추고 승인 받기)
업체별 표로 보여 준다: 업체 · 제보 값 · 근거와 출처 · 판정 · 반영할 값 · 시트에 쓸 상태와 검토 메모(한 줄). 일치 건만 "반영 제안"으로 묶는다. **사용자가 승인한 항목만** 5단계로 간다. 승인이 없으면 파일을 하나도 고치지 않는다.

## 5. 반영 (승인된 일치 건만)
- 입장료·수건·주차 가격 → `data/curated/onsen_prices.csv`의 해당 카카오ID 줄(없으면 새 줄). 칸: 카카오ID, 성인_평일, 성인_주말, 수건, 주차, 어린이, 추가요금_없음확인, 메모, 출처, 확인일. 출처에는 **제보가 아니라 확인한 근거**(예: 네이버 플레이스 가격표)를 적고, 확인일은 오늘(KST).
- 세신 금액·수건 정책·드라이기·**세신 결제** → `data/curated/place_facts.json`(제보의 수건 안내 `무제한/1장/2장/3장 이상`은 `towel`의 `mode`·`count`로, 드라이기 `무료/유료`는 `hairdryer.paid`로, 세신 결제 `현금만/카드 가능`은 `seshin.payment`의 `cash_only/card_ok`로 옮긴다. 남탕·여탕이 다르다는 메모가 있으면 성별을 나눠 적는다. 근거를 확인한 것만)의 `places[카카오ID]`. 기존 모양(`seshin.price_full`, `towel.women/men`, `hairdryer.paid`, `checked`, `source`)을 따르고, **없는 칸은 적지 않는다**(추측 금지).
- 파일 인코딩은 `utf-8-sig`(BOM 포함), CSV는 번호 칸 없이 쓴다. 기존 줄 모양(따옴표·줄 끝)을 그대로 따른다.
- 이어서 `cargo run --release --bin export_web_data`로 화면 데이터를 다시 만들고, 반영 전후의 확인된 요금 업체 수를 조건과 함께 비교해 보여 준다. 그다음 `web`에서 `npm run build`가 통과하는지 확인한다.
- **커밋·푸시는 사용자가 말할 때만** 한다. 하기 전에 `git status`를 보여 주고 이번 작업과 관계없는 변경은 넣지 않는다.

## 6. 시트 갱신
승인된 판정대로 해당 줄의 `상태`(K열)와 `검토 메모`(L열: 근거와 날짜를 한 줄로)를 고친다. ego-browser로 시트 셀을 편집하고, Drive 연결로 다시 읽어서 바뀌었는지 확인한다. ego-browser의 제어권이 사용자에게 있으면 **스스로 되찾지 않고** 사용자가 "계속"이라고 할 때까지 기다린다. 브라우저를 쓸 수 없으면 줄 번호별로 넣을 값을 표로 주고 사용자가 직접 붙여 넣게 한다.

## 7. 마무리 보고
처리한 제보 수(반영 / 반려 / 확인함 / 반영 불가), 바뀐 파일, 다음에 할 일(확인 못 함 건의 추가 근거)을 짧게 적는다. Notion 기록은 사용자가 요청할 때만 남긴다.

## 지킬 것
- 제보 값을 근거 없이 화면 데이터에 넣지 않는다. 사람이 확인한 값만 `data/curated/`에 둔다.
- 개인 이름·전화번호는 어디에도 옮기지 않는다. 메모에 연락처가 있으면 `[연락처 의심, 가림]`으로만 다룬다. `제보자(해시)`·`접속(해시)` 칸은 읽지도 옮기지도 않는다.
- 비밀 값(`REPORT_SHEET_URL`, `REPORT_SHEET_SECRET`)은 열어 보지도, 출력하지도 않는다.
- 숫자(개수·평균)는 코드로 계산하고 어떤 조건으로 셌는지 같이 적는다.
- 삭제는 사용자가 말했을 때만 한다. 시트 줄도 지우지 않고 상태로만 관리한다.
